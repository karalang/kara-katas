# 238. Product of Array Except Self

Return an array `out` where `out[i]` is the product of every element of `nums`
**except** `nums[i]` — **without division**, in `O(n)` time and `O(1)` extra
space (the output array is not counted against the space bound).

## Approach

Two sweeps over the output array itself:

1. **left → right:** `out[i]` receives the product of everything strictly *left*
   of `i` (a running prefix product).
2. **right → left:** multiply each `out[i]` by a running product of everything
   strictly *right* of `i` (a suffix product folded in).

After both passes `out[i] = (∏ left of i) × (∏ right of i) = ∏ except i`. Zeros
fall out for free: one zero zeroes every other position; two zeros zero
everything.

## Files

- [`product_except_self.kara`](product_except_self.kara) — Kāra implementation.
- [`product_except_self.py`](product_except_self.py) — Python mirror (oracle).

Expected output (both):

```
24 12 8 6
0 0 9 0 0
12 8 6
9 5
```

### Three workload-design decisions, all load-bearing

This kata took three attempts to size honestly, and each failure would have
produced a benchmark that looked fine:

1. **Values are bounded to `{-1, 1}`.** The algorithm multiplies a running
   product across the whole array, so arbitrary values overflow `i64` within
   ~20 elements. Kāra traps integer overflow by default, so the benchmark would
   have aborted rather than measured. LeetCode's own constraint guarantees the
   product fits in 32 bits, so a bounded-product input is representative.
2. **Zeros are excluded.** With `{-1, 0, 1}`, a 100 000-element draw contains
   two zeros with near-certainty, which zeroes every output and collapses the
   sink to `0` — an oracle a completely broken implementation would also
   satisfy. The kata's own tests cover the zero path.
3. **Values come from LCG bit 16, not bit 0.** A power-of-two-modulus LCG has
   **period 2 in its low bit**, so `x % 2` produces a perfectly alternating
   `1,-1,1,-1,…`. With 8 arrays whose starting parity splits evenly, the
   position-weighted sums then cancel to *exactly* zero — the sink was still
   `0` after fixing (2), for an entirely different reason.

### A cross-language `%` trap

The sink is negative, and **Python's `%` floors while Kāra, Rust, C and Go all
truncate toward zero.** Using Python's operator directly makes the oracle
disagree with the other four on a perfectly correct computation. The Python
mirror applies an explicit `trunc_mod`; all five then agree.
